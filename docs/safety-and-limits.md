# 安全与方法局限

## 生成代码不是普通数据

实验 B 的 `binpack_eval.py` 会调用 Python `exec`。AST 黑名单、受限 builtins、独立子进程、临时目录和超时都不构成完整安全沙箱。仍可能有资源耗尽、运行器或评分器被干扰等问题。

默认 CLI 拒绝执行生成代码。只有在可丢弃、无个人或生产数据、受 CPU/内存/时间限制的独立环境中，才应显式开启；网络访问也需要在环境层限制。代码没有自动提供这些隔离能力。

离线验证只使用仓库里已阅读的固定函数。如果你改动证据文件中的源码，也要重新检查，不能因为文件名叫 evidence 就信任它。

## 配置与数据

公开版不扫描用户目录或秘密文件，只用显式环境变量。更换 API 账号、地区或服务需要你自己确认，不会自动回退到其他提供商。新运行的模型输入输出可能含你放入的内容，分享前需要审阅。

## 评估限制

- 合成题的成功不等于真实业务任务成功。
- 原型将最终失败调用计为错误答案；连续服务失败可能影响分数，需要另行区分基础设施错误。
- bootstrap 是按题重采样；不是对多次完整优化过程进行重复验证。
- 优化集与留出集参与选择，只有最终 test 留作最后比较。
- 留出集只看观测平均值非负，不是正式非劣检验。
- 输出解析器、候选编辑器和评分器都有局限，候选提出的理由也可能错误。
- 装箱的固定混合分布、种子、规模和评分方式限制了泛化范围。
- 原程序的参数随机采样与并发没有提供完整确定性复现保证。

因此本仓库称为“优化实验”，不将两段小程序等同于完整的递归自我改进系统，也不与其他论文的 benchmark 数字直接比较。
